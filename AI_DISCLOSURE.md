# AI Disclosure

## 1. AI tools used during development

The team used an **AI coding assistant** extensively during development, under the team's
direction. It helped with:

* analysing the benchmark and published MTEB results,
* implementing most of the code, the tests and the web demo,
* running the experiments and the evaluations,
* drafting the documentation and the presentation content.

The team defined the goals and priorities, supplied the official materials, made the final
decisions, reviewed and tested the system, ran the official evaluation, recorded the demo
video, and is responsible for the submission.

## 2. AI / ML models used *inside* the system at runtime

| Model | Role | Generative? |
|---|---|---|
| [`codefuse-ai/F2LLM-v2-0.6B`](https://huggingface.co/codefuse-ai/F2LLM-v2-0.6B) (Apache-2.0) | Text/code embedding model for dense retrieval, run locally on CPU | No; it only produces vectors |

No large language model is called at query time, and nothing is generated. As the problem
statement requires, the system only *retrieves and ranks* existing snippets. The re-ranking
evidence comes from **executing** candidate snippets on the query's own sample tests in a
local sandbox, not from an LLM. No external AI API is used, and no data leaves the machine
except the one-time download of the model and dataset from Hugging Face.

## 3. Data

* CoIR `apps` dataset (`CoIR-Retrieval/apps`, revision pinned to the one MTEB uses) for
  evaluation.
* Fusion weights are hand-set priors, never tuned on retrieval rankings. They were chosen
  after an execution-only feasibility study on 600 sampled test queries (see README,
  "Evidence fusion").
* The evolution-benchmark versions are synthetic, generated by deterministic AST transforms
  in `src/litmus/evolve.py`.

## 4. Honesty statement

All numbers reported in the README and the presentation come from scripts in this
repository, run on the stated hardware. The official AppsRetrieval result files are in
`results/`.
