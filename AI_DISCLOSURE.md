# AI Disclosure

This document describes, as accurately as we can, how AI was used to build this
submission.

## 1. AI used during development

| Item | Details |
|---|---|
| Tool | **Claude Code** (Anthropic's agentic coding assistant), model *Claude Opus 5.5*, running in the Claude desktop app on the team's laptop |
| Scope | Almost all of the engineering work was carried out by the AI agent, directed and reviewed by the team |
| What the team provided | The official PRISM materials (`theme1_guidelines.pdf`, the PPT template), the goal ("build the strongest submission"), priorities and the deadline, and review / approval of the result |

What the AI agent did:

* **Problem analysis:** read the Theme-1 guidelines and the PPT template, inspected the
  CoIR-apps dataset, and pulled published `AppsRetrieval` scores from the public MTEB
  results repository to compare models.
* **Design decisions:** chose the embedding model (F2LLM-v2-0.6B) from published scores
  and CPU measurements, and identified the execution-verification idea from the dataset
  structure (98% of test queries contain sample tests). It also designed the versioned
  content-addressed store.
* **Experiments:** CPU throughput benchmarks (dtype, batch size, threads, OpenVINO, int8),
  an execution-feasibility study, and the subset / evolution evaluations whose numbers
  appear in `results/`.
* **Code:** every module under `src/litmus`, the scripts, tests and the web UI.
* **Documents:** README, this disclosure, the demo script, the submission checklist, and
  the content added to the PPT template.

The team is responsible for the submission and has reviewed it.

## 2. AI / ML models used *inside* the system at runtime

| Model | Role | Generative? |
|---|---|---|
| [`codefuse-ai/F2LLM-v2-0.6B`](https://huggingface.co/codefuse-ai/F2LLM-v2-0.6B) (Apache-2.0) | Text/code embedding model for dense retrieval, run locally on CPU | No; it only produces vectors |

No large language model is called at query time, and nothing is generated. As the
problem statement requires, the system only *retrieves and ranks* existing snippets. The
re-ranking evidence comes from **executing** candidate snippets on the query's own
sample tests in a local sandbox, not from an LLM.

No external AI API is used by the system, and no data leaves the machine except for the
one-time download of the model and dataset from Hugging Face.

## 3. Data

* CoIR `apps` dataset (`CoIR-Retrieval/apps`, revision pinned to the one MTEB uses) for
  evaluation.
* Fusion weights are hand-set priors, never tuned on retrieval rankings. They were chosen
  after an execution-only feasibility study on 600 sampled test queries (see README,
  "Evidence fusion").
* The evolution benchmark versions are synthetic, generated by deterministic AST
  transforms in `src/litmus/evolve.py`. No AI generated that data.

## 4. Honesty statement

All numbers reported in the README and the presentation come from scripts in this
repository run on the stated hardware. Anything that was not run is labelled
**pending**.
